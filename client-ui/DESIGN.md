# client-ui 设计规范

适用于 iPhone、iPad、visionOS (嵌入 `NshAppView`) 与桌面浏览器 (Daemon 托管)。依据 NSH Design Guides, 只记录这个应用自己的决定。

## 目标平台

- **触屏 (iOS、iPadOS、visionOS、手机浏览器):** 控件不小于 44pt, 正文 16pt 起, 底部标签栏, 查看器是全屏层。
- **桌面与 Web (`platform.desktop`):** 紧凑控件 (32pt), 顶部标签栏, 键盘优先, hover 与可见焦点环。
- 判断只用 `platform.desktop` / `platform.os`, 不用屏幕宽度猜设备。

## Token

颜色只通过 `theme.json` 的 token 使用, 代码里没有十六进制或调色板类。

| Token | 用途 |
|---|---|
| `primary` / `primary-foreground` | 主操作、选中的标签、进度 |
| `success` | 已完成、Engine 运行中 |
| `warning` | Engine 启动中、提示条 |
| `destructive` / `destructive-foreground` | 失败、危险操作、错误文字 |
| `muted` / `muted-foreground` | 次要文字、占位、轨道 |
| `card`、`border`、`input`、`ring` | 表面、分隔线、输入框边框、焦点环 |

浅色与深色各一组值, 跟随系统。圆角统一 `rounded-(--radius)` (12pt)。

## ui 层

`src/ui/` 是应用自己的组件层, 页面只组合它们, 不直接用 `nsh/base` 的控件, 也不写颜色、圆角、字号:

`Icon` (自绘线条图标)、`Button` / `IconButton` (primary、secondary、ghost、destructive)、`TextField` / `NumberField` / `SwitchField` / `SelectField`、`Card`、`Badge`、`Banner`、`Empty`、`Spinner` / `Meter`、`Segmented` / `NavTabs`、`ToastHost`。

页面需要而 `ui` 没有的外观, 先加成 `ui` 的变体再用。

## 任务页的排序与重排

- **一次性排序:** 页头的「排序」打开一张菜单: 名称 (升序 / 降序)、日期 (从旧到新 / 从新到旧)、大小 (从小到大 / 从大到小)。选一项就把当前所有条目 (不分状态) 排一次, 之后新加入的追加在末尾, 不会自动维持排序。缺日期或大小的条目不论升降都排在末尾, 值相同的保持原有的相对顺序。名称是自然序 (page2 在 page10 前, 不分大小写)。少于两项时按钮置灰。
- **单项移动:** 每一行 / 每一格有「更多」按钮, 菜单里「移到最前」「移到最后」; 已经在那里的一项置灰。
- **拖动:** 触屏上长按 0.4 秒后拖, 鼠标按下后移动 5 点后拖; 列表和网格都一样。被拖的那一格变淡 (30%) 当占位, 一个跟手的影子 (原样的行 / 格, 90% 不透明) 盖在列表上, 落点用主色的指示线标出: 列表里是落下那一行的上缘 (往前拖) 或下缘 (往后拖) 的横线, 网格里是落下那一格旁边间隙里的竖线。指针靠近列表上下边缘 72 点时自动滚动 (最快每秒 1100 点)。拖动中列表本身不滚动; 放手时才改顺序, 没动或落回原位什么也不改。拖动不触发点按 (不会打开查看器)。
- **只是显示顺序:** 这些操作不影响 Pending Upload 提交给 Daemon 的先后, 也不影响 Daemon 的队列。
- 不做键盘移动。菜单是自己画的卡片 (嵌入 iOS 的运行时没有 Menu、Popover、Sheet), 点卡片外或按 Esc 收起。

## 重复的图片

导入时跳过「同一张图换了分辨率或重新压缩」的图片, 免得同一页翻译两次。判断用最轻量的指纹, 不比文件字节, 也不上传 Daemon:

- **指纹:** 宿主在导入时用解码好的 256 像素的图 (和缩略图是同一次解码) 算一个 256 位的差分哈希 (dHash): 缩成 17 列 16 行的灰度 (每格取它盖住的像素的灰度平均, 全部整数运算), 每行 17 个值两两比较得 16 位, 左边比右边亮超过 3 个灰度级记 1, 共 16 x 16 = 256 位, 64 个十六进制字符。App 用 ImageIO (`ImageFingerprint.swift`), Web 用 `createImageBitmap` 加 canvas (`web/host.js`), 两边的算法是同一份 (整数、同样的格子划分、同样的位序), 用同样的 6 组黄金样本测, 都过就是位级一致。宿主解码出的 256 像素图略有差别, 所以同一个文件两边的哈希不一定相同 (见下面实测), 但判断只在一个设备上的一个列表里做, 不跨设备。
- **判定:** 汉明距离 ≤ 20 并且宽高比相差不到 3% (`|a - b| / max(a, b)`; 有一边没有宽高比就不拿它否决)。比较范围是当前列表里所有条目 (待上传、上传中、被拒绝、已成为 Job 的, 不分状态; 已移除的不算) 和同一批里更早的。没有指纹的 (格式解不开、宿主没算出来) 一律照常加入。
- **提示:** 被跳过的显示「已跳过 N 张重复图片」, 带「仍然添加」。按它把被跳过的那些加进来 (不再比较); 提示消失时它们在宿主里的副本被放掉。提示还在的时候又有新的重复到来, 数目累加, 一个按钮加回全部。
- **指纹随条目保存** (和名字、大小一起, 成为 Job 之后也留着), 所以重启后新导入的图还是要和已有的比。
- **PDF:** 宿主按内容的 SHA-256 (App 用 CryptoKit 每次读 1 MB 流式算, Web 用自己的 JS 实现一块块读 File, 因为局域网的 http 页面没有 `crypto.subtle`) 认同一个文件: 再导入时不留第二份, 把已有的那份交给 TSX 打开; 正是现在开着的那份就什么都不动 (页码和各页的翻译进度都留着), 只提示「这个 PDF 已经打开了」。

**阈值是怎么定的** (`scripts/fingerprint-study/study.py`, 2026-11-16, 在 Mac 上跑, 量的是 App 里同一份 Swift 代码)。基图 53 张: 4 张真实漫画页 (`imgs/`、`crates/runtimes/simple-runtime/in/`、`/tmp/s12-work/img` 的 small2; s12 的 small1 与其中一张字节相同, 没有重复计入)、一条 800x15000 的真实长图切出的 13 个相邻的页、6 张合成页 (`/tmp/nsh-ui-work/imgs`)、30 张合成的近空白页 (留白加纸的颗粒和几个小记号)。没有更多真实漫画页可用, 所以异图里真实页的组合只有 17 张的 136 对, 其余有合成的; 这是这次实测最大的缺口。每张基图做 11 个变体: Lanczos 缩放 0.25x、0.5x、0.75x、1.5x、2x, JPEG 质量 90、70、50、30, 缩 0.5x 再 JPEG 50, 以及 `sips` 缩 0.5x。

| | 距离 (汉明, 256 位) |
|---|---|
| 同图的变体, 页 (n=253) | 最大 12, p99 11, 中位数 1 |
| 同图的变体, 近空白页 (n=330) | 最大 7, p99 6 |
| 不同的页 (n=253 对) | 最近 45 (不算下一行), p1 49, 中位数 101 |
| 一页和近空白页 (n=690 对) | 最近 24, 中位数 60 |
| 近空白页彼此 (n=435 对) | 全部是 0 |
| `real-sample-a` 对 `real-sample-c` (推测是同一页的原图和译图, 没有看图, 只凭距离小判断) | 8 |

- **死区 (margin):** 朴素的 dHash (margin 0) 同图的页最远 19 位、近空白页最远 35 位 (平坦区域里纸的噪声让差分位随机翻转); margin 3 时分别是 12 和 7, 而不同的页最近仍是 45。margin 6 以上不同的页开始靠近 (37、30), 所以取 3。
- **阈值 20:** 同图最远 12 (留 8 位), 一页和近空白页最近 24 (留 4 位), 不同的页最近 45。0 到 12 位时同图的漏判从 59% 降到 0, 之后到 20 都是 0; 24 起一页和近空白页开始误判 (30 对), 所以没取 24。
- **同图里宽高比差最大 0.08%** (缩放取整), 远小于 3%。
- **已知的限制:** (1) 17x16 的格子看不见小东西: 近空白页彼此的哈希完全一样 (距离 0), 一页只有页码和几行字时会被当成另一页只有页码和几行字的重复。这种误判靠「仍然添加」补救, 但没人看提示就会漏。(2) 如果上面那一对确实是原图和译图, 版式一样的两张距离只有 8, 会被当成重复 (多数时候这正是想要的)。(3) 同图的 JPEG 重压缩、缩放之外的变化 (裁边、旋转、加水印、调色) 没有测。(4) 阈值只用了很少的真实漫画页定, 换一批真实页应该重跑 `study.py` 看分布 (`study.py <工作目录> <额外的图片目录>` 把目录里的图当作异图加入)。
- **App 与 Web 对同一个文件算出的哈希** (223 个文件, 含各种变体, Chrome 解码 对 ImageIO 解码): 距离最小 0、中位数 2、p90 5、p99 11、最大 12, 41 个完全相同。解码器的缩放滤波不同, 算法本身一致 (黄金样本)。

## 还没上传的条目

待上传、上传中、被 Daemon 拒绝的条目永远显示名字和状态徽章, 缩略图用宿主导入时生成的小图 (`thumb`, 见 HOST_PROTOCOL.md); 宿主给不出就是占位图标, 不会是空白。成为 Job 之后换用 Daemon 的降采样预览。被拒绝的条目在列表里 (一行一项) 还会多一行怎么办的提示, 「格式不支持」就是 HEIC、AVIF 这类 Daemon 读不了的格式转不了 (宿主能转的在导入时已经转了)。

## 状态

每个会变的东西都有可见的状态, 而且不只靠颜色: 任务状态是文字 (排队中 · 翻译中 · 已完成 · 失败 · 已取消) 加色标; 表单错误是红字说明; 禁用是 `disabled:opacity-40` 加不可按; 键盘高亮行有 `bg-accent`, 焦点用 `focus-visible:ring-2`。

## 键盘

| 位置 | 按键 | 行为 |
|---|---|---|
| 任务列表 | ↑ ↓ | 移动高亮 (到头停住, 移出屏幕才滚动) |
| 任务列表 | Enter / 空格 | 打开高亮的已完成任务 |
| 任务列表 | Delete | 移除高亮项 |
| 查看器 | ← ↑ / → ↓ | 上一张 / 下一张已完成任务 |
| 查看器 | 空格 | 译文与原文互换 (与 PDF 阅读器的空格一致) |
| 查看器 | Esc | 关闭 |
| PDF 阅读器 | ← ↑ / → ↓ | 上一页 / 下一页 (按住连翻, 到头停住) |
| PDF 阅读器 | 空格 | 未翻译的页加入 Queue; 翻译完的页在原文与译文间互换 (与查看器一致)。有译文的页默认显示译文 (打开、翻页、译文刚完成时); 切回原文后, 这个文档里所有已翻译的页和之后翻译完的页都保持原文, 直到再按一次; 偏好属于文档, 随 `reader.last` 保存, 换一个文档回到译文 |
| 表单 | Enter | 提交 (配对页) |

输入框获得焦点时, 方向键和空格交给输入框, 不触发上面的绑定 (NSH keymap 的默认行为)。

## 动效清单

| 变化 | 工具 | 说明 |
|---|---|---|
| 按下反馈 | `active:opacity-70` | 所有按钮、列表行 |
| 开关滑块 | `transition-transform` / `transition-colors` | `SwitchField` 的轨道与滑块 |
| 分段控件与标签的指示条 | `Tabs` 的 `indicatorClass`, 原生滑动 | `Segmented` |
| 列表增删与状态变化 | 无 | 行原地更新; 批量任务每秒都在变, 动画只会增加噪音 |
| 拖动重排 | 无 | 影子随手指移动, 指示线直接出现, 放手时顺序直接换; 动画只会让落点晚一拍 |
| 排序与移动 | 无 | 顺序直接换, 同上 |
| 提示条 (toast) 出现与消失 | 无 | 3.5 秒自动收起, 点按立即收起 |
| PDF 阅读器翻页与译文叠层 | 无 | 按住方向键要立即连翻, 原文与译文直接互换 |
| 查看器进入 | 无 | 全屏层直接出现, 切图不做转场, 方向键连按要立即响应 |

尊重「减少动态效果」: 以上动效都由 NSH 的类与原生指示条提供, 系统设置开启时由 NSH 处理。

## 完成检查

每次改界面按 Design Guides 的 Finishing checklist 看浅色与深色截图: 圆角、字号、间距、对齐、颜色、hover、按下、各种状态、动效。截图存 `/tmp/nsh-ui-shots` 对照。
